Big picture

One look instead of many

Two-stage (Faster R-CNN)

Propose regions first, then classify each one. Accurate but several steps.

YOLO

Treat detection as one regression problem: the network reads the whole image once and outputs boxes, confidence and classes together.

Why that matters

Simple, fast and trainable end to end, so it became the default for cameras, drones, robots and edge devices.

Demo 1

The grid: who is responsible?

YOLOv1 splits the image into an S × S grid. The cell that contains the center of an object is responsible for predicting it. Move the object and change the grid size.

each cell predicts: B boxes × (x, y, w, h, confidence) + C class probabilities output = S × S × (B·5 + C)

Paper setup: S = 7, B = 2, C = 20 (Pascal VOC) → 7 × 7 × 30. Limits of v1: each cell predicts only a few boxes and one class, so groups of tiny objects are hard.

Demo 2

Scores, thresholds and NMS

The network outputs many overlapping boxes. Two filters clean them up: a confidence threshold and Non-Maximum Suppression.

score = Pr(class | object) × confidence confidence = Pr(object) × IoU(pred, truth)

Solid = kept · dashed red = removed by NMS · gray dots = below the confidence threshold. Lower the NMS IoU and more overlapping boxes disappear; raise it and duplicates survive.

Anchor-based (v2 to v5)

bx = σ(tx) + cx by = σ(ty) + cy bw = pw·e^tw bh = ph·e^th

Predicts offsets from preset anchor shapes (found with k-means on your boxes).

Anchor-free, decoupled head (v8+)

Predicts box distances directly, with separate branches for box and class. No anchor tuning, simpler and often more accurate.

Loss

Box loss (IoU-based, e.g. CIoU) + objectness/class loss. v1 used squared error with extra weight on coordinates.

Model sizes (YOLOv8, approx.)

Parameters (M, gray) and COCO mAP50-95 (black). Figures follow the Ultralytics docs; check the current page for exact numbers and newer models.

Settings that matter

  • conf: lower = more boxes, more false alarms
  • iou: NMS overlap threshold
  • imgsz: larger helps small objects, slower
  • epochs, batch

Tips for good results

  • Data quality beats model size: consistent labels, varied light, angles and backgrounds.
  • Add background images (no objects) to cut false positives.
  • Start from pretrained weights and fine-tune.
  • Read the confusion matrix and failure cases, not only mAP.
  • On edge devices, export (ONNX and others), pick n or s, shrink imgsz, and measure real FPS on the device.

Self-check


Why is YOLO fast?One network pass predicts boxes and classes together. There is no separate region-proposal step.


What is the YOLOv1 output tensor?S × S × (B·5 + C); with S=7, B=2, C=20 that is 7 × 7 × 30.


What is the confidence score made of?Pr(object) × IoU(prediction, truth). Multiply by the class probability for the class-specific score.


Why three detection scales?Small, medium and large objects appear best on feature maps of different resolution (strides 8, 16, 32).


Anchor-based vs anchor-free?Anchor-based predicts offsets from preset shapes; anchor-free predicts boxes directly, with less tuning.


What do conf and NMS iou change?conf drops weak boxes; NMS iou decides how much overlap is tolerated before a box is removed as a duplicate.


Common mistakesPixel values instead of normalized labels; class IDs not matching data.yaml; testing on training images; extreme conf values; ignoring the license.
