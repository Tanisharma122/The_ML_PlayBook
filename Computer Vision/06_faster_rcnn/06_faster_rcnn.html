Big picture

From R-CNN to Faster R-CNN

Each version fixed the biggest bottleneck of the one before.

R-CNN (2014)

Find ~2000 candidate regions with Selective Search, resize each, run a CNN on every one, classify with SVMs.

Problem: ~2000 CNN passes per image. Very slow.

→

Fast R-CNN (2015)

Run the CNN once on the whole image, then cut each region out of the shared feature map with RoI pooling.

Problem: Selective Search is still slow and separate.

→

Faster R-CNN (2015)

Replace Selective Search with a small Region Proposal Network (RPN) that shares the CNN features and is learned.

Whole detector is one trainable network.

The one-line idea: shared features → learned proposals → per-region classification and box refinement. The original paper reports about 5 frames per second on a GPU with VGG-16.

Anchors and the RPN

At every feature-map position the RPN considers 9 anchors (3 scales × 3 aspect ratios). Move the position and watch which anchors would be labeled positive (IoU > 0.7 with the dashed ground-truth box), negative (IoU < 0.3) or ignored.

anchor w = s / √r, h = s · √r scales s: 3 ratios r: 3 (1:2, 1:1, 2:1) k = 9 anchors per position

800×800 image, stride 16 → 50 × 50 positions × 9 = 22,500 anchors. The RPN outputs 2k = 18 scores and 4k = 36 offsets per position.

Box regression targets

tx = (x − xa) / wa ty = (y − ya) / ha tw = log(w / wa) th = log(h / ha)

The network predicts these offsets from anchor a to the truth. Predicting a shift and a log-scale keeps values small and stable.

RoI Pooling vs RoIAlign

RoI Pooling rounds region edges to whole feature cells, so features shift slightly.
RoIAlign keeps exact coordinates and samples with bilinear interpolation. It is more precise and is standard today (introduced with Mask R-CNN).

Math

The loss

L = (1/Ncls) Σ Lcls(pi, pi*) + λ (1/Nreg) Σ pi* · Lreg(ti, ti*)

pi = predicted object probability, pi* = 1 for positive anchors, 0 for negative. The regression term only counts positives. The same structure is used again in the detection head, with a class instead of object/background.

smooth_L1(x) = 0.5·x² if |x| < 1 |x| − 0.5 otherwise

Smooth L1 acts like L2 near zero (smooth gradient) and like L1 for big errors, so outliers do not dominate training.

Details

Training and inference

RPN training

  • Positive anchor: IoU > 0.7 with a truth box (or the best anchor for that box)
  • Negative: IoU < 0.3 with all boxes
  • Sample 256 anchors per image, up to a 1:1 positive:negative ratio
  • Anchors crossing the image border are ignored in training

Detection head training

  • Proposals with IoU ≥ 0.5 to a truth box are foreground, labeled with that box's class
  • Lower-IoU proposals are background
  • Sample a fixed number per image with about 25% foreground

Joint training

The paper first used a 4-step alternating scheme (train RPN, train detector, share layers, fine-tune). Modern code trains end to end with the combined loss.

Inference

  • RPN proposals → NMS (IoU 0.7) → keep a few hundred
  • Head scores each proposal, refines boxes
  • Score threshold, then per-class NMS
Beyond

Variants and comparison

FPN

A feature pyramid with strong meaning at every scale. Proposals are assigned to the level that fits their size. Big gain for small objects. Standard setup: ResNet-50 + FPN.

Mask R-CNN

Adds a mask branch (and RoIAlign) for instance segmentation; also used for keypoints.

Cascade R-CNN

Several heads with rising IoU thresholds for sharper localization.

Self-check


Why is it called two-stage?Stage 1 (the RPN) proposes regions that may hold objects. Stage 2 classifies each proposal and refines its box.


What does the RPN output at each position?For k anchors: 2k objectness scores (object or background) and 4k box offsets.


How are RPN anchors labeled?Positive if IoU > 0.7 with a truth box (or best match), negative if IoU < 0.3, the rest ignored.


Why share the backbone between RPN and head?Features are computed once, so proposals are almost free compared with Selective Search, and both parts learn from the same features.


RoI Pooling vs RoIAlign?Pooling quantizes coordinates and causes misalignment. RoIAlign uses bilinear sampling at exact positions.


Why smooth L1 for boxes?Gentle near zero and linear for large errors, so it is less sensitive to outliers than L2.


When would you choose it over YOLO?When accuracy and localization quality matter more than speed, or for small and crowded objects on a capable GPU.


Common mistakesUsing label 0 for a real class; wrong box format; forgetting model.eval(); not replacing the head when your class count differs from COCO; expecting real-time speed on a CPU.
