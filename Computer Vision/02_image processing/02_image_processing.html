IMAGE PROCESSING

Transforming raw pixels into useful visual information.

Image processing applies numerical operations to an image array to enhance it, clean it, or expose structure, so a person or a model can use it. Every demo below runs on real pixel data in your browser, using a canvas and plain JavaScript implementations of the same algorithms OpenCV uses.

01 — WHAT IS IT?From the world to a model

A camera samples light onto a grid of sensors. Each sensor reports a number, so an image is simply an array. Processing changes those numbers on purpose: preprocessing makes data consistent (size, range, noise), and feature operations (thresholds, edges) expose structure. A processed image is a new array, not a "better" one in general; it is better only for a specific task.

Real world→Camera→Digital image→Pixels→Image processing→Useful information→CV / ML model

02 — IMAGE AS NUMBERSPixel Explorer

Hover (or touch) the image. Grayscale is H × W; colour is H × W × 3. A pixel is one grid cell, a channel is one number layer per pixel, width/height are columns/rows, and resolution is the pixel count (W×H). In NumPy, img[y, x] is row first.

05 — BRIGHTNESS & CONTRASToutput = α × input + β

α (contrast) stretches the gap between dark and bright; β (brightness) slides every value up or down. Results are clipped to 0–255, which destroys detail (saturation). The histogram shows what happens.

07 — IMAGE NOISENoise Laboratory

Noise is unwanted random variation. Causes: low light and high ISO (Gaussian-like sensor noise), thermal effects, compression, and transmission errors or dead pixels (salt-and-pepper). Noise adds false gradients, which breaks thresholds and edge detectors.

10 — EDGE DETECTIONEdge Laboratory

An edge is a rapid change in intensity. Sobel estimates the horizontal and vertical derivatives; the gradient magnitude is √(Gx²+Gy²). Canny smooths, computes gradients, thins edges with non-maximum suppression, then uses hysteresis: pixels above the high threshold are kept, and pixels between low and high are kept only if connected to a strong one.

cv2.Canny(gray, low, high)

13–14 — AI/ML AND USESWhere it fits

Raw image→Preprocessing→Model input tensor→CNN / vision model→Prediction

Image processing manipulates pixels; computer vision extracts meaning; machine learning learns patterns from data; deep learning uses multi-layer networks (CNNs, ViTs). Deep models learn many features themselves, but resizing, normalisation, noise handling and standardisation remain standard so inputs match training data.

17 — COMMON MISTAKESAvoid these




Width vs height. img.shape is (H, W, C) but cv2.resize takes (W, H).


RGB vs BGR. OpenCV is BGR; convert before plotting or feeding RGB-trained models.


Data types. uint8 overflows (250+10 wraps to 4). Convert to float32 before maths, and clip back.


Too much blur. Destroys small details and weak edges.


Bad thresholds. One global T fails on uneven lighting; use adaptive or Otsu. Canny low/high far apart or too high gives broken or empty edges.


Always-better assumption. Preprocessing is task dependent; it can discard information a model needs. Match training-time preprocessing at inference.

20 — KEY TAKEAWAYSSummary


IMAGE=PIXELS+CHANNELS+NUMERICAL VALUES

IMAGE PROCESSING=TRANSFORMING IMAGE DATA FOR A SPECIFIC PURPOSE


Images are arrays (H×W×C). Geometry changes layout; point operations (brightness, contrast, threshold) change values independently; filters and edges use neighbourhoods; morphology reshapes binary regions. Order matters: denoise before edges, and always match the preprocessing your model expects.
